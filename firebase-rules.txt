====================================================================
REGRAS DO FIRESTORE - Cloud Firestore > Rules
====================================================================

Cole estas regras no Console do Firebase:
Firebase Console > Firestore Database > Rules

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // ---------------------------------------------------------------
    // COLEÇÃO: usuarios
    // Armazena dados de autenticação/autorização de cada usuário.
    // Estrutura do documento:
    //   uid (id doc)
    //   nome: string
    //   email: string
    //   role: 'admin' | 'colaborador'
    //   status: 'pendente' | 'aprovado'
    //   total_score: number
    //   criado_em: timestamp
    //   aprovado_em: timestamp (nullable)
    //   aprovado_por: string (nullable)
    // ---------------------------------------------------------------

    match /usuarios/{userId} {

      // Verifica se o usuário logado é admin
      function isAdmin() {
        return request.auth != null &&
          get(/databases/$(database)/documents/usuarios/$(request.auth.uid)).data.role == 'admin';
      }

      // Verifica se o usuário logado está aprovado
      function isAprovado() {
        return request.auth != null &&
          get(/databases/$(database)/documents/usuarios/$(request.auth.uid)).data.status == 'aprovado';
      }

      // Leitura:
      // - Dono lê o próprio documento
      // - Admin lê tudo
      // - Usuários aprovados também podem ler (necessário para ranking)
      allow read: if request.auth != null && (
        request.auth.uid == userId ||
        isAdmin() ||
        isAprovado()
      );

      // Criação: só o próprio usuário, com status obrigatoriamente 'pendente'
      allow create: if request.auth != null &&
        request.auth.uid == userId &&
        request.resource.data.status == 'pendente';

      // Atualização/Exclusão: apenas admin (para aprovar, alterar role, etc.)
      allow update, delete: if isAdmin();
    }

    // ---------------------------------------------------------------
    // DEMAIS MÓDULOS (atividades, módulos do sistema, etc.)
    // ---------------------------------------------------------------
    match /modulos_sistema/{document=**} {
      // Apenas usuários aprovados ou admin podem ler/escrever
      allow read, write: if isAprovado() || isAdmin();
    }

  }
}

====================================================================
CONFIGURAÇÃO DO FIREBASE AUTH
====================================================================

Firebase Console > Authentication > Sign-in method:
- Habilitar "E-mail/Senha"

====================================================================
FLUXO DE APROVAÇÃO
====================================================================

1. Usuário se cadastra → documento em /usuarios/{uid} com status:'pendente'
2. Usuário tenta acessar o dashboard → redirecionado para aguardando.html
3. Admin vê usuários pendentes no painel Admin e clica "Aprovar"
4. Admin atualiza status para 'aprovado' no documento do usuário
5. Usuário é redirecionado automaticamente para o dashboard

====================================================================
CRIAR ADMIN INICIAL (MANUAL - VIA CONSOLE)
====================================================================

1. Crie um usuário pelo formulário de cadastro normalmente
2. No Firebase Console > Firestore > Coleção "usuarios"
3. Edite o documento do admin: role: "admin", status: "aprovado"

====================================================================
CRIAR ADMIN INICIAL (VIA SCRIPT - RECOMENDADO)
====================================================================

1. Crie o usuário admin pelo formulário de cadastro (register.html)
2. No Firebase Console > Configurações > Contas de Serviço >
   "Gerar nova chave privada" → salvar como serviceAccountKey.json
   na raiz do projeto

3. Instale as dependências:
   cd scripts
   npm install

4. Execute o seed:
   node scripts/seed-admin.js

O script vai buscar o usuário pelo e-mail (brayan@storsistemas.com.br)
e criar/atualizar o documento dele com role: "admin", status: "aprovado".

ATENÇÃO: serviceAccountKey.json está no .gitignore e NUNCA deve
ser commitado.

====================================================================
ÍNDICES DO FIRESTORE
====================================================================

Índice necessário para listar usuários pendentes:
  Collection: usuarios
  Fields: status (asc), criado_em (asc)
